# .NET SDK installation & PATH setup (Windows)

This file contains step-by-step instructions to install the .NET 8 SDK, ensure the dotnet CLI is on your PATH, and prepare the environment to run Entity Framework Core CLI commands (dotnet ef) and apply migrations.

1) Install .NET 8 SDK
   - Download the .NET 8 SDK installer for Windows from:
     https://dotnet.microsoft.com/en-us/download/dotnet/8.0
   - Run the installer (x64) and follow the prompts. The installer normally adds dotnet to the system PATH.

2) Open a new terminal and verify dotnet is available
   - Close any open Command Prompt / PowerShell / VS Code terminals and open a fresh one.
   - Run:
       dotnet --info
     You should see SDK and runtime details. If you still see "'dotnet' is not recognized", continue to step 3 to add it to PATH.

3) Add dotnet to PATH (if needed)
   - Typical installation locations:
       C:\Program Files\dotnet\
       C:\Users\<your-username>\.dotnet\tools
   - To add these to your User PATH:
     - Open Windows Settings → System → About → Advanced system settings → Environment Variables
     - Under "User variables" select PATH → Edit → New and add both paths above (replace <your-username> appropriately).
     - Click OK and restart your terminal.
   - Alternatively from PowerShell (run as the user who will use dotnet):
       $userPath = [Environment]::GetEnvironmentVariable('PATH','User')
       $newEntries = 'C:\\Program Files\\dotnet;C:\\Users\\' + $env:USERNAME + '\\.dotnet\\tools'
       [Environment]::SetEnvironmentVariable('PATH', ($userPath + ';' + $newEntries), 'User')
     Then restart your terminal session.

4) Install dotnet-ef (global tool)
   - In a new terminal run:
       dotnet tool install --global dotnet-ef
   - Ensure the global tools folder (%USERPROFILE%\\.dotnet\\tools) is on PATH (see step 3). Verify with:
       dotnet ef --info

5) SQL Server for local development
   - Use SQL Server Developer/Express (install via Microsoft site) or point to an existing SQL Server.
   - Example connection string used by the project:
       Server=.;Database=InsuranceManagementDb;Integrated Security=True;TrustServerCertificate=True;
   - Verify connectivity using SQL Server Management Studio (SSMS) or sqlcmd:
       sqlcmd -S . -Q "select name from sys.databases"

6) Re-run EF migration & database update (after dotnet is available)
   - From the repository root (d:\\Projects\\InsuranceManagementSystem) run:
       dotnet ef database update -p Insurance-Backend\\Insurance.Infrastructure -s Insurance-Backend\\Insurance.Api --connection "Server=.;Database=InsuranceManagementDb;Integrated Security=True;TrustServerCertificate=True;"
   - Note: when invoking from PowerShell, wrap the connection string in single or double quotes so it is treated as a single argument.

7) Troubleshooting
   - If 'dotnet' is not found after installation: restart terminals or sign out/in if PATH changes don't show up.
   - If 'dotnet ef' is not found: ensure dotnet-ef is installed and %USERPROFILE%\\.dotnet\\tools is on PATH.
   - If SQL connection fails: ensure SQL Server service is running, firewall allows local connections, and the instance name in the connection string is correct.
